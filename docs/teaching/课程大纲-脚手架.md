# 课程大纲 — 脚手架：完整演示 + 工程化结构 + AI 协作入门

> **时长**：10-15 分钟  
> **定位**：所有 Agent 项目的第一节课，让学员看到全貌、理解结构、学会用 Cursor 扩展  
> **前提**：无需编程经验，重点是"理解 + 会用"，不是从零写代码

---

## 步骤 1：完整演示（3 分钟）

> **目标**：先让学员看到"这个脚手架长什么样、能干什么"，建立直觉

### 说什么

> "我们先不看代码，先看这个脚手架做出来的东西长什么样。所有后续的 Agent 项目——知识库、AIGC、智能客服——都是在这个脚手架上长出来的。"

### 屏幕展示什么

#### 1.1 登录页（30 秒）

- **展示**：浏览器打开 `http://localhost:13006`，展示登录页面
- **操作**：点击「游客访问」按钮
- **说明**："这里有正常登录和游客模式，游客不需要后端，直接体验 UI"

#### 1.2 工作台 Dashboard（30 秒）

- **展示**：登录后的控制台页面
- **操作**：简单浏览各区块——统计卡片、销售概览图表、新用户/活跃用户、待办事项
- **说明**："这是工作台，数据是 Mock 的，实际项目里对接真实 API 就行"

#### 1.3 管理员视角（30 秒）

- **展示**：说明游客看不到「系统管理」，再用 `admin/admin123` 登录后依次点开用户管理、角色管理、菜单管理
- **操作**：展示表格、搜索、分页、新增/编辑弹窗
- **说明**："标准的后台管理 CRUD 页面，以后你的业务页面就长这样"

#### 1.4 主题切换 + 国际化（30 秒）

- **展示**：右上角设置面板
- **操作**：
  1. 切换暗色主题 → 切回亮色
  2. 切换语言 English → 切回中文
- **说明**："暗色主题、国际化，这些功能脚手架都内置了，不用自己写"

#### 1.5 异常页（30 秒）

- **展示**：点开异常页面（403/404/500）
- **操作**：快速浏览
- **说明**："异常页、结果页这些通用组件也都有，直接用就行"

## 步骤 2：项目结构速览（3 分钟）

> **目标**：让学员理解"代码在哪里"，前后端怎么分的

### 说什么

> "看完了长什么样，我们打开 IDE 看看代码是怎么组织的。你不需要记住每个文件，只需要知道'找东西去哪找'。"

### 屏幕展示什么

#### 2.1 项目根目录（30 秒）

- **展示**：在 Cursor 中打开项目根目录
- **说明**：
  ```
  infra-dev-scaffolding/
  ├── frontend/      ← Vue 3 + Vite 前端
  ├── backend/       ← Spring Boot 后端
  ├── docs/          ← 文档
  └── README.md      ← 项目说明
  ```
- **强调**："整个项目就两大块——前端和后端，物理分离，互不干扰"

#### 2.2 前端目录结构（1 分钟）

- **展示**：展开 `frontend/src/` 目录树
- **逐个点开说明**：

| 目录 | 一句话说明 | 展示方式 |
|------|----------|---------|
| `views/` | 页面放这里 | 展开看到 auth/dashboard/system |
| `router/` | 路由在这里配 | 打开 `router/modules/` 看模块化路由 |
| `api/` | 前端调后端的接口 | 展开看到 auth.ts / user.ts |
| `components/` | 通用组件 | 提一下 core/ 下的布局组件 |
| `store/` | Pinia 状态管理 | 提一下 user/menu/setting |
| `locales/` | 国际化语言包 | 展开看 zh.json / en.json |
| `config/` | 配置中心 | 提一下主题、菜单等配置 |

- **说明**："想加新页面？去 `views/` 建文件，去 `router/` 配路由。想加新接口？去 `api/` 写。结构很清晰"

#### 2.3 后端目录结构（1 分钟）

- **展示**：展开 `backend/src/main/java/com/anjing/` 目录树
- **逐个点开说明**：

| 目录 | 一句话说明 | 展示方式 |
|------|----------|---------|
| `controller/` | 接口入口 | 打开看到 AuthController、TestController |
| `config/` | 配置类 | 提一下 redis/、properties/ |
| `model/` | 数据模型 | 展开看 request/response/errorcode |
| `aspect/` | AOP 切面 | 提一下日志、分布式锁 |
| `util/` | 工具类 | 提一下 JsonUtils、PasswordUtils |
| `example/` | 功能示例 | 提一下远程调用、状态机 |

- **说明**："后端是标准的 Controller → Service → Repository 分层，想加新接口就从 Controller 开始写"

## 步骤 3：Cursor AI 协作亮点（4 分钟）

> **目标**：这是本课最核心的部分——现场演示用标准 Prompts 生成一个完整业务模块，学员能看到 AI 如何按工程契约拆分前后端代码

### 说什么

> "这个脚手架最大的亮点，不是代码本身，而是它内置了一套完整的 Cursor AI 协作配置——前端 11 条规则、后端 4 条规则，以及 6 个代码生成模板。我现在给大家演示一下，用标准 Prompts 生成公告管理模块。后端、前端 API、列表页、弹窗分步生成，每一步都有工程契约。"

### 屏幕展示什么

#### 3.1 先快速展示 Rules（30 秒）

- **展示**：在 Cursor 侧边栏展开 `frontend/.cursor/rules/` 目录
- **操作**：不用逐个打开，只展示文件列表
- **说明**："这里有 11 条前端规范、后端也有 4 条。AI 写代码时会自动遵守这些规范，等下你就能看到效果。"

#### 3.2 现场演示：用 Prompts 生成公告管理模块（3.5 分钟）

- **前提**：建议在临时分支或复制项目中演示，完整参数见 `docs/teaching/04-notice-module-demo.md`
- **操作流程**：

1. **后端 CRUD**：选择 `backend/.cursor/prompts/crud-module.md`
   - 模块名称：公告管理
   - 实体名称：Notice
   - 表名：t_notice
   - API 前缀：/api/notices
   - 重点检查：列表响应字段为 `records`、`current`、`size`、`total`
2. **前端 API**：选择 `frontend/.cursor/prompts/api-module.md`
   - API 文件：`src/api/notice.ts`
   - Model 文件：`src/api/model/noticeModel.ts`
   - 重点检查：删除请求使用 `request.del`
3. **前端列表页**：选择 `frontend/.cursor/prompts/vue-list-page.md`
   - 页面：`src/views/notice/index.vue`
   - 搜索组件：`src/views/notice/modules/notice-search.vue`
   - 重点检查：使用 `ArtTable`、`ArtTableHeader` 和 `useTable`
4. **前端弹窗**：选择 `frontend/.cursor/prompts/vue-modal-form.md`
   - 组件：`src/views/notice/components/NoticeDialog.vue`
   - 重点检查：`visible` 使用 `defineModel`，成功后 emit `success`
5. **路由注册**：新增 `frontend/src/router/modules/notice.ts`，并在 `frontend/src/router/modules/index.ts` 加入 `routeModules`
6. **验收**：运行 `mvn -q -DskipTests package`、`pnpm build` 和 `./scripts/check-template.sh`

- **预期效果**：
  - 侧边栏出现「公告管理」菜单
  - 点进去是完整的列表页，表格字段、搜索、分页、编辑和删除都符合项目现有风格
  - 后端生成标准的 Entity、Repository、Service、Controller、Request、VO 和 ErrorCode
  - 生成代码不进入 `example` 包，也不添加 `@ScaffoldSample`

- **讲解要点**（边等 AI 生成边说）：
  - "注意看，我们不是让 AI 随便写，而是让它按 Prompt 契约分层生成。"
  - "后端列表响应为什么要叫 `records/current/size/total`？因为前端 `useTable` 和 `PaginatedResponse<T>` 就吃这套结构。"
  - "前端删除为什么是 `request.del`？因为这就是项目 HTTP 工具真实暴露的方法。"
  - "**这就是脚手架的核心价值：规范沉淀在 Rules 和 Prompts 里，AI 按规范干活，人负责验收和边界。**"

> **录制提示**：
> - 建议录制前先在复制项目里跑一遍完整流程
> - 如果 AI 生成超过 90 秒，可用预录片段剪辑
> - 演示结束后，母版主分支只保留 `docs/teaching/04-notice-module-demo.md`，不要把公告业务代码长期留在母版里

## 步骤 4：怎么基于脚手架长出新项目（2 分钟）

> **目标**：让学员明白后续课程的工作方式

### 说什么

> "这个脚手架不是让你天天看的，而是让你复制出去，在上面长出新项目。后面的知识库、AIGC、客服项目，都是这么来的。"

### 屏幕展示什么

#### 4.1 fork 流程（1 分钟）

- **展示**：打开 README.md，滚动到「基于脚手架创建新项目」章节
- **念出关键步骤**（不需要实际操作）：
  ```
  第一步：复制项目  cp -r infra-dev-scaffolding my-new-project
  第二步：改标识    改 pom.xml / package.json / application.yml 里的项目名
  第三步：清理示例  前端运行 pnpm clean:dev 做 dry-run，后端按 TEMPLATE_BOUNDARIES.md 处理 TestController 和 example/
  第四步：加业务    用 Cursor Prompts 生成新的页面和接口
  ```
- **说明**："就四步，复制 → 改名 → 清理 → 开发。以后的每个项目都是这个流程"

#### 4.2 保留什么 vs 删除什么（1 分钟）

- **展示**：用两列对比（可以口述，也可以展示提前准备好的对比）：

| 保留（骨架） | 删除（示例） |
|-------------|------------|
| Cursor Rules + Prompts | TestController |
| 全局异常处理 | example/ 目录 |
| 统一响应 APIResponse | 演示页面（Dashboard 数据） |
| 权限框架 | Mock 数据 |
| 主题 / 国际化 | — |
| 工具类 / 配置类 | — |

- **说明**："骨架保留，示例删除。前端 `pnpm clean:dev` 先做残留检查，确认后再 `pnpm clean:dev -- --apply`"

## 步骤 5：核心配置概览（2 分钟）

> **目标**：让学员知道"哪些能力可以开关"，按需启停

### 说什么

> "最后看一下配置。这个脚手架的中间件和功能都是可配置的，不需要的就关掉，不会报错。"

### 屏幕展示什么

#### 5.1 后端中间件开关（1 分钟）

- **展示**：打开 `backend/src/main/resources/application.yml`，滚动到 `app.features` 部分
- **操作**：高亮展示以下配置项：

```yaml
app:
  features:
    redis:
      enabled: true        # Redis 缓存——不装 Redis 就改 false
    distributed-lock:
      enabled: true        # 分布式锁
      provider: redisson   # 可改成 local（本地锁，无需 Redis）
    database:
      enabled: true        # 数据库
    middleware:
      kafka:
        enabled: false     # Kafka——默认关闭
      minio:
        enabled: false     # MinIO——默认关闭
```

- **说明**：
  - "每个中间件都有开关，`enabled: false` 就完全不加载，即使你没装这个软件也不报错"
  - "比如你本地没装 Redis，把 redis.enabled 改成 false 就行"
  - "分布式锁还支持降级到本地锁，单机开发不需要 Redis"

#### 5.2 前端配置速览（1 分钟）

- **展示**：打开 `frontend/.env.development`
- **说明**：
  ```
  VITE_BASE_URL = /          ← 部署路径
  VITE_API_URL = /           ← API 地址（开发用 /，走 Vite 代理）
  VITE_API_PROXY_URL = http://localhost:18080   ← 后端地址
  ```
- **操作**：提一下游客模式的配置
  - "前端 `.env` 里有个 `VITE_ACCESS_MODE = frontend`，这是游客模式的前提"
- **说明**："前端配置很简单，改个后端地址、部署路径就行"
