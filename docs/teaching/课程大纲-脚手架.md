# 课程大纲 — 脚手架：完整演示 + 工程化结构 + AI 协作入门

> **时长**：10-15 分钟  
> **定位**：所有 Agent 项目的第一节课，让学员看到全貌、理解结构、学会用 Cursor 扩展  
> **前提**：无需编程经验，重点是"理解 + 会用"，不是从零写代码

---

## 步骤 1：完整演示（3 分钟）

> **目标**：先让学员看到"这个脚手架长什么样、能干什么"，建立直觉

### 说什么

> "我们先不看代码，先看这个脚手架做出来的东西长什么样。所有后续的 Agent 项目——知识库、AIGC、智能客服——都是在这个脚手架上长出来的。"

### 屏幕展示什么

#### 1.1 登录页（30 秒）

- **展示**：浏览器打开 `http://localhost:13006`，展示登录页面
- **操作**：点击「游客访问」按钮
- **说明**："这里有正常登录和游客模式，游客不需要后端，直接体验 UI"

#### 1.2 工作台 Dashboard（30 秒）

- **展示**：登录后的控制台页面
- **操作**：简单浏览各区块——统计卡片、销售概览图表、新用户/活跃用户、待办事项
- **说明**："这是工作台，数据是 Mock 的，实际项目里对接真实 API 就行"

#### 1.3 系统管理（30 秒）

- **展示**：依次点开「系统管理」下的用户管理、角色管理、菜单管理
- **操作**：展示表格、搜索、分页、新增/编辑弹窗
- **说明**："标准的后台管理 CRUD 页面，以后你的业务页面就长这样"

#### 1.4 主题切换 + 国际化（30 秒）

- **展示**：右上角设置面板
- **操作**：
  1. 切换暗色主题 → 切回亮色
  2. 切换语言 English → 切回中文
- **说明**："暗色主题、国际化，这些功能脚手架都内置了，不用自己写"

#### 1.5 异常页（30 秒）

- **展示**：点开异常页面（403/404/500）
- **操作**：快速浏览
- **说明**："异常页、结果页这些通用组件也都有，直接用就行"

## 步骤 2：项目结构速览（3 分钟）

> **目标**：让学员理解"代码在哪里"，前后端怎么分的

### 说什么

> "看完了长什么样，我们打开 IDE 看看代码是怎么组织的。你不需要记住每个文件，只需要知道'找东西去哪找'。"

### 屏幕展示什么

#### 2.1 项目根目录（30 秒）

- **展示**：在 Cursor 中打开项目根目录
- **说明**：
  ```
  agent-dev-scaffolding/
  ├── frontend/      ← Vue 3 + Vite 前端
  ├── backend/       ← Spring Boot 后端
  ├── docs/          ← 文档
  └── README.md      ← 项目说明
  ```
- **强调**："整个项目就两大块——前端和后端，物理分离，互不干扰"

#### 2.2 前端目录结构（1 分钟）

- **展示**：展开 `frontend/src/` 目录树
- **逐个点开说明**：

| 目录 | 一句话说明 | 展示方式 |
|------|----------|---------|
| `views/` | 页面放这里 | 展开看到 auth/dashboard/system |
| `router/` | 路由在这里配 | 打开 `routes/modules/` 看模块化路由 |
| `api/` | 前端调后端的接口 | 展开看到 auth.ts / user.ts |
| `components/` | 通用组件 | 提一下 core/ 下的布局组件 |
| `store/` | Pinia 状态管理 | 提一下 user/menu/setting |
| `locales/` | 国际化语言包 | 展开看 zh.json / en.json |
| `config/` | 配置中心 | 提一下主题、菜单等配置 |

- **说明**："想加新页面？去 `views/` 建文件，去 `router/` 配路由。想加新接口？去 `api/` 写。结构很清晰"

#### 2.3 后端目录结构（1 分钟）

- **展示**：展开 `backend/src/main/java/com/anjing/` 目录树
- **逐个点开说明**：

| 目录 | 一句话说明 | 展示方式 |
|------|----------|---------|
| `controller/` | 接口入口 | 打开看到 AuthController、TestController |
| `config/` | 配置类 | 提一下 redis/、properties/ |
| `model/` | 数据模型 | 展开看 request/response/errorcode |
| `aspect/` | AOP 切面 | 提一下日志、分布式锁 |
| `util/` | 工具类 | 提一下 JsonUtils、PasswordUtils |
| `example/` | 功能示例 | 提一下远程调用、状态机 |

- **说明**："后端是标准的 Controller → Service → Repository 分层，想加新接口就从 Controller 开始写"

## 步骤 3：Cursor AI 协作亮点（4 分钟）

> **目标**：这是本课最核心的部分——现场演示"一段提示词，前后端一起生成一个完整功能"，学员能亲眼看到后端日志打印

### 说什么

> "这个脚手架最大的亮点，不是代码本身，而是它内置了一套完整的 Cursor AI 协作配置——17 条编码规范、6 个代码生成模板。我现在给大家演示一下，用一段提示词，让 AI 同时生成前端页面和后端接口，真正跑起来。"

### 屏幕展示什么

#### 3.1 先快速展示 Rules（30 秒）

- **展示**：在 Cursor 侧边栏展开 `frontend/.cursor/rules/` 目录
- **操作**：不用逐个打开，只展示文件列表
- **说明**："这里有 12 条前端规范、后端也有 5 条。AI 写代码时会自动遵守这些规范，等下你就能看到效果。"

#### 3.2 现场演示：一段提示词生成前后端完整功能（3.5 分钟）

- **前提**：后端已启动（`mvn spring-boot:run`），前端已启动（`pnpm dev`）
- **操作流程**：

1. **打开 Cursor 对话框**（`Cmd+L` 或 `Cmd+I`）
2. **粘贴以下提示词**（提前复制好，课上直接粘贴）：

---

**【演示用提示词 — 录制前提前复制到剪贴板】**

```
我在做一个企业级全栈脚手架项目，代码在 /Users/lvxianghe/project/anjing-project/agent-dev-scaffolding，前端在 frontend/（Vue3 + Element Plus + TypeScript），后端在 backend/（Spring Boot + Java 17）。

请帮我新增一个「公告管理」功能，前后端都要做：

## 后端（backend/）

1. 新增 NoticeController，放在 com.anjing.controller 包下
2. 路径前缀 /api/notices
3. 用内存 Map 存储数据（不用数据库），参考现有的 TestController 写法
4. 提供以下接口：
   - GET /api/notices — 查询公告列表（支持 keyword 关键词搜索）
   - POST /api/notices — 新增公告
   - DELETE /api/notices/{id} — 删除公告
5. 启动时预置 3 条示例公告数据（系统升级通知、放假通知、新功能上线）
6. 每个接口都要有 log.info 日志打印
7. 统一使用 APIResponse 返回

## 前端（frontend/）

1. 新增页面 src/views/notice/index.vue
2. 新增路由 src/router/modules/notice.ts，路径 /notice，菜单名用国际化 key，图标 ri:megaphone-line，不限制角色（游客也能看到）
3. 在 src/router/modules/index.ts 中注册路由
4. 在 zh.json 和 en.json 的 menus 下新增 notice 翻译（公告管理 / Notice）
5. 新增 API 文件 src/api/notice.ts，调用后端真实接口
6. 页面包含：搜索栏（关键词 + 搜索按钮）、表格（标题/发布人/发布时间/状态标签/操作列）、分页组件
7. 操作列有"删除"按钮，调后端删除接口，删除后刷新列表

请参考现有代码的风格和规范。
```

---

3. **等待 AI 生成**（通常 60-90 秒）
4. **Apply 所有文件**
5. **切到浏览器刷新**，点击侧边栏「公告管理」
6. **切到后端终端**，展示日志输出

- **预期效果**：
  - 侧边栏出现「公告管理」菜单
  - 点进去是完整的列表页，表格里有 3 条预置公告
  - 点"删除"按钮，公告消失，后端终端打出删除日志
  - 搜索栏输入关键词，列表实时过滤
  - 切换英文，菜单名变成 "Notice"

- **讲解要点**（边等 AI 生成边说）：
  - "注意看，我只描述了要什么功能，没有指定用什么组件库、什么代码风格。但 AI 会自动用 Element Plus、`<script setup>`、TypeScript——因为 `.cursor/rules/` 里的规范它全读了"
  - "后端也一样，自动用了 `APIResponse` 统一响应、`@Slf4j` 日志、`@RestController` 注解——这些都是后端 rules 里规定的"
  - "**这就是脚手架的核心价值：你定好规范，AI 按规范干活**"

- **生成完毕后展示后端日志**：
  - 切到后端终端，指着日志说："看，后端真的收到了请求，日志都打出来了。这不是 Mock，是真正的前后端联调"

> **录制提示**：
> - 建议录制前先跑一遍确认效果，确认后 `git checkout .` 还原，录制时再跑
> - 如果 AI 生成超过 90 秒，可用预录片段剪辑
> - 确保后端已启动且终端日志可见

### 屏幕展示什么

#### 4.1 fork 流程（1 分钟）

- **展示**：打开 README.md，滚动到「基于脚手架创建新项目」章节
- **念出关键步骤**（不需要实际操作）：

  第一步：复制项目  cp -r agent-dev-scaffolding my-new-project
  第二步：改标识    改 pom.xml / package.json / application.yml 里的项目名

#### 4.2 保留什么 vs 删除什么（1 分钟）

## 步骤 5：核心配置概览（2 分钟）

> **目标**：让学员知道"哪些能力可以开关"，按需启停

### 说什么

> "最后看一下配置。这个脚手架的中间件和功能都是可配置的，不需要的就关掉，不会报错。"

### 屏幕展示什么

#### 5.1 后端中间件开关（1 分钟）

- **展示**：打开 `backend/src/main/resources/application.yml`，滚动到 `app.features` 部分
- **操作**：高亮展示以下配置项：

```yaml
app:
  features:
    redis:
      enabled: true        # Redis 缓存——不装 Redis 就改 false
    distributed-lock:
      enabled: true        # 分布式锁
      provider: redisson   # 可改成 local（本地锁，无需 Redis）
    database:
      enabled: true        # 数据库
    middleware:
      kafka:
        enabled: false     # Kafka——默认关闭
      minio:
        enabled: false     # MinIO——默认关闭
```

- **说明**：
  - "每个中间件都有开关，`enabled: false` 就完全不加载，即使你没装这个软件也不报错"
  - "比如你本地没装 Redis，把 redis.enabled 改成 false 就行"
  - "分布式锁还支持降级到本地锁，单机开发不需要 Redis"

#### 5.2 前端配置速览（1 分钟）

- **展示**：打开 `frontend/.env.development`
- **说明**：
  ```
  VITE_BASE_URL = /          ← 部署路径
  VITE_API_URL = /           ← API 地址（开发用 /，走 Vite 代理）
  VITE_API_PROXY_URL = http://localhost:18080   ← 后端地址
  ```
- **操作**：提一下游客模式的配置
  - "前端 `.env` 里有个 `VITE_ACCESS_MODE = frontend`，这是游客模式的前提"
- **说明**："前端配置很简单，改个后端地址、部署路径就行"
